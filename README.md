# Библиотека шифров

Локальное веб-приложение для хранения и поиска шифров: слово-шифр, описание и теги.
Теги образуют дерево любой глубины (у тега может быть до двух родителей); поиск по тегу находит шифры
со всеми его потомками.

## Требования

- Node.js 20.19+ (проверено на Node.js 24)
- npm 10+

Docker, внешние базы данных и регистрация не нужны — всё хранится в локальном файле SQLite.

## Установка

```bash
npm install
```

`npm install` также генерирует Prisma Client.

## Запуск

```bash
npm run dev
```

Команда применяет миграции (при первом запуске создаёт базу) и запускает сразу два процесса:

- интерфейс — http://localhost:5173 (откройте его в браузере);
- API — http://127.0.0.1:3001.

### Режим без dev-сервера

```bash
npm run build
npm start
```

Сервер сам отдаёт собранный интерфейс: всё приложение доступно на http://127.0.0.1:3001.

### Другие команды

| Команда             | Что делает                                   |
| ------------------- | -------------------------------------------- |
| `npm run typecheck` | Проверка типов клиента и сервера             |
| `npm test`          | Тесты логики тегов (нормализация, дерево, циклы, цвета) и сортировки шифров |
| `npm run db:migrate`| Применить миграции базы вручную              |

## Где лежат данные

- **База SQLite:** `data/ciphers.db`
- **Резервные копии:** `backups/backup-ГГГГ-ММ-ДД.sqlite`

Копия базы создаётся автоматически при старте сервера, а если приложение работает долго — раз в сутки.
Хранятся 30 последних копий. Чтобы восстановить данные, остановите приложение и скопируйте нужный
файл из `backups/` на место `data/ciphers.db`.

    styles/             тема и общие стили

  src/
    routes/             REST-маршруты /api/ciphers и /api/tags

## API

| Метод  | Адрес                          | Описание                                        |
| ------ | ------------------------------ | ----------------------------------------------- |
| GET    | `/api/ciphers?q=мар&tags=1,5&sort=date-desc` | Список шифров с поиском, фильтром и сортировкой |
| POST   | `/api/ciphers`                 | Создать шифр                                    |
| GET    | `/api/ciphers/:id`             | Один шифр                                       |
| PUT    | `/api/ciphers/:id`             | Изменить шифр (слово, описание, теги и их порядок) |
| DELETE | `/api/ciphers/:id`             | Удалить шифр                                    |
| GET    | `/api/tags`                    | Все теги плоским списком (`parentIds` задаёт дерево) |
| POST   | `/api/tags`                    | Создать тег                                     |
| PUT    | `/api/tags/:id`                | Изменить название, цвет или родителей           |
| DELETE | `/api/tags/:id`                | Удалить тег                                     |

Тело шифра: `{ "word": "Марс", "description": "…", "tags": [{ "id": 3 }, { "name": "Новый тег" }] }` —
существующие теги передаются по `id`, новые по `name` (сервер создаст их или использует уже существующий
тег с тем же названием). Порядок массива — порядок тегов у шифра.

Тело тега: `{ "name": "Шоколад", "color": "#9d86dc", "parentIds": [4, 7] }` — не больше двух родителей.

Сортировка шифров (`sort`): `name-asc` (по умолчанию), `name-desc`, `date-desc`, `date-asc`, `tags-desc`, `tags-asc`.
При сортировке по количеству тегов считаются только непосредственно назначенные шифру теги.

## Как работают теги

- Название нормализуется: «еда», «ЕДА» и « Еда » превращаются в «Еда». Уникальность проверяется
  без учёта регистра (`Tag.normalizedName` — уникальный индекс), похожие названия («Шоколад» и
  «Шоколадка») считаются разными.
- У тега 0, 1 или 2 родителя (таблица связей `TagParent`), детей и глубина не ограничены. Тег с двумя
  родителями — одна запись, которая видна в обеих ветках. Любой тег, в том числе родительский, можно
  назначить шифру напрямую.
- Фильтр по тегу находит шифры с этим тегом и со всеми его потомками по всем веткам. Несколько фильтров и
  текстовый поиск объединяются через И (AND): «Еда + Сладости» — это ветка Сладостей. Логика выполняется
  на сервере.
- В списке тегов на странице шифров нажатие на тег выбирает его и показывает его детей, повторное —
  снимает фильтр и сворачивает детей. Теги сгруппированы по цвету: сначала цвета, которыми окрашено
  больше всего тегов, внутри цвета — по алфавиту.
- Если шифру добавляют тег, а у шифра уже есть его предок или потомок, форма спрашивает, что оставить;
  сама она ничего не удаляет.
- Кроме 8 базовых цветов в палитре есть свои цвета, которыми сейчас окрашен хотя бы один тег. Отдельно
  они не хранятся: когда последний тег такого цвета перекрашен или удалён, цвет пропадает из палитры.
- Новый тег из поля тегов в форме шифра создаётся сразу — с выбранным цветом (по умолчанию серым).
- На карточке шифра показываются только непосредственно назначенные теги — в том порядке, в котором
  их расставили (порядок меняется перетаскиванием в форме).
- Сервер запрещает делать тег родителем самого себя или своего потомка (циклы).
- При удалении тега шифры сохраняются, связи с тегом удаляются, а дочерние теги остаются под вторым
  родителем, если он есть, иначе становятся корневыми.
- Связи шифров с тегами хранятся по `id`, поэтому переименование тега сразу видно во всех шифрах.
