# Библиотека шифров

Локальное веб-приложение для хранения и поиска шифров: слово-шифр, описание и теги.
Теги образуют дерево любой глубины; поиск по тегу находит шифры со всеми его потомками.

## Требования

- Node.js 20.19+ (проверено на Node.js 24)
- npm 10+

Docker, внешние базы данных и регистрация не нужны — всё хранится в локальном файле SQLite.

## Установка

```bash
npm install
```

`npm install` также генерирует Prisma Client.

## Запуск

```bash
npm run dev
```

Команда применяет миграции (при первом запуске создаёт базу) и запускает сразу два процесса:

- интерфейс — http://localhost:5173 (откройте его в браузере);
- API — http://127.0.0.1:3001.

### Режим без dev-сервера

```bash
npm run build
npm start
```

Сервер сам отдаёт собранный интерфейс: всё приложение доступно на http://127.0.0.1:3001.

### Другие команды

| Команда             | Что делает                                   |
| ------------------- | -------------------------------------------- |
| `npm run typecheck` | Проверка типов клиента и сервера             |
| `npm test`          | Тесты логики тегов (нормализация, дерево, циклы) |
| `npm run db:migrate`| Применить миграции базы вручную              |

## Где лежат данные

- **База SQLite:** `data/ciphers.db`
- **Резервные копии:** `backups/backup-ГГГГ-ММ-ДД.sqlite`

Копия базы создаётся автоматически при старте сервера, а если приложение работает долго — раз в сутки.
Хранятся 30 последних копий. Чтобы восстановить данные, остановите приложение и скопируйте нужный
файл из `backups/` на место `data/ciphers.db`.

## Структура проекта

```text
client/                 фронтенд: React + TypeScript + Vite
  src/
    api/                HTTP-слой: запросы к REST API и обработка ошибок
    components/         общие компоненты: TagChip, TagInput, ConfirmDialog, …
    context/            TagsContext — единый список тегов для всего приложения
    hooks/              useCiphers, useDebouncedValue, useDragReorder
    lib/                логика тегов на клиенте: индекс дерева, поиск, контраст цветов
    pages/
      CiphersPage/      страница «Шифры»: поиск, фильтр по тегам, карточки, форма
      TagsPage/         страница «Теги»: дерево, формы, выбор цвета, удаление
    styles/             тема и общие стили
server/                 бэкенд: Node.js + Express + TypeScript
  src/
    routes/             REST-маршруты /api/ciphers и /api/tags
    services/           бизнес-логика: теги (уникальность, циклы, удаление) и шифры (фильтрация)
    validation.ts       проверка входных данных (zod)
    backup.ts           ежедневные резервные копии базы
shared/                 код, общий для клиента и сервера: типы API, правила названий тегов, дерево
prisma/                 схема базы и миграции
data/                   файл базы SQLite
backups/                резервные копии (создаются автоматически)
```

## API

| Метод  | Адрес                          | Описание                                        |
| ------ | ------------------------------ | ----------------------------------------------- |
| GET    | `/api/ciphers?q=мар&tags=1,5`  | Список шифров по алфавиту, с поиском и фильтром |
| POST   | `/api/ciphers`                 | Создать шифр                                    |
| GET    | `/api/ciphers/:id`             | Один шифр                                       |
| PUT    | `/api/ciphers/:id`             | Изменить шифр (слово, описание, теги и их порядок) |
| DELETE | `/api/ciphers/:id`             | Удалить шифр                                    |
| GET    | `/api/tags`                    | Все теги плоским списком (`parentId` задаёт дерево) |
| POST   | `/api/tags`                    | Создать тег                                     |
| PUT    | `/api/tags/:id`                | Изменить название, цвет или родителя            |
| DELETE | `/api/tags/:id`                | Удалить тег                                     |

Тело шифра: `{ "word": "Марс", "description": "…", "tags": [{ "id": 3 }, { "name": "Новый тег" }] }` —
существующие теги передаются по `id`, новые по `name` (сервер создаст их или использует уже существующий
тег с тем же названием). Порядок массива — порядок тегов у шифра.

## Как работают теги

- Название нормализуется: «еда», «ЕДА» и « Еда » превращаются в «Еда». Уникальность проверяется
  без учёта регистра (`Tag.normalizedName` — уникальный индекс), похожие названия («Шоколад» и
  «Шоколадка») считаются разными.
- У тега 0 или 1 родитель, глубина не ограничена. Любой тег, в том числе родительский, можно
  назначить шифру напрямую.
- Фильтр по тегу находит шифры с этим тегом и со всеми его потомками. Несколько фильтров и текстовый
  поиск объединяются через И (AND). Логика выполняется на сервере.
- На карточке шифра показываются только непосредственно назначенные теги — в том порядке, в котором
  их расставили (порядок меняется перетаскиванием в форме).
- Сервер запрещает делать тег родителем самого себя или своего потомка (циклы).
- При удалении тега шифры сохраняются, связи с тегом удаляются, а дочерние теги становятся корневыми.
- Связи шифров с тегами хранятся по `id`, поэтому переименование тега сразу видно во всех шифрах.
